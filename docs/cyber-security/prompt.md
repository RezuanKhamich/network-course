# Промт для генерации курса «Информационная безопасность для разработчиков»

Промт рассчитан на генерацию по одному модулю за запуск: так проще держать качество и проверять результат. Подставьте номер модуля и его блок из [structure.json](structure.json), приложите тексты тем roadmap.sh, перечисленных в `topics` уроков (файлы `roadmaps/cyber-security/content/<slug>@<id>.md` в репозитории [developer-roadmap](https://github.com/nilbuild/developer-roadmap)).

Отдельные промты в конце файла: для `course.js` (виджеты, сквозной сценарий, шпаргалки) и для глоссария.

---

## Промт: контент модуля

```text
Ты — автор технических курсов и практикующий специалист по информационной безопасности.
Пишешь модуль {MODULE_ID} «{MODULE_TITLE}» для курса «Информационная безопасность для
разработчиков» на сайте с интерактивными курсами. Курс построен по roadmap.sh/cyber-security.

АУДИТОРИЯ
Разработчики и начинающие специалисты ИБ. Умеют программировать, работали с Git, HTTP и
командной строкой. В безопасности новички. Цель — чтобы после урока человек понимал механизм,
узнавал проблему в своём коде или инфраструктуре и знал, что делать.

ВХОДНЫЕ ДАННЫЕ
1. Структура модуля (уроки, их id, названия и темы roadmap.sh):
{MODULE_JSON}
2. Тексты тем roadmap.sh — опорный список того, что нужно покрыть. Это не источник для перевода:
пиши своими словами, проверяй факты, дополняй тем, что нужно на практике.
{ROADMAP_TOPICS}

ЧТО СДЕЛАТЬ
Верни один JavaScript-объект модуля (без `const`, без пояснений до и после) строго такой формы:

{
 id: {MODULE_ID}, title: '{MODULE_TITLE}', short: '{MODULE_SHORT}',
 lessons: [
  { id: '{M}-1', title: '…', topics: ['slug', …], html: `…`, check: [ {вопрос}, {вопрос} ] },
  …
 ],
 test: [ 12 вопросов ]
}

Поля `id`, `title`, `topics` уроков бери из структуры без изменений.

УРОК (поле html)
- Объём 1500–2500 символов разметки. Один урок — одна мысль, без воды и вступлений
  «В этом уроке мы рассмотрим».
- Структура: 1–2 абзаца о сути → 2–4 раздела с <h3> → практика (команда, код, конфиг, пример
  лога) → блок «Зачем это разработчику» или «Частая ошибка».
- Каждая атака подаётся по схеме: как работает → как заметить (признаки в логах, трафике,
  поведении) → как защититься (конкретные настройки, код, политики).
- Разрешённая разметка: <p>, <h3>, <b>, <i>, <code>, <pre><code>…</code></pre>, <ul>/<ol>/<li>,
  <ol class="steps"> для последовательностей, <a href> на первоисточники (RFC, OWASP, NIST,
  MITRE, документация вендора), и блоки:
    <div class="note why"><b>Зачем это разработчику.</b> …</div>
    <div class="note warn"><b>Частая ошибка.</b> …</div>
    <div class="tbl"><table><tr><th>…</th></tr><tr><td>…</td></tr></table></div>
    <div data-widget="{id}"></div> — только если виджет назначен этому уроку в structure.md.
  Без инлайн-стилей, без <script>, без картинок.
- Внутри html это JS-шаблонная строка: экранируй ` и ${ (\` и \${), а символы < > & внутри
  примеров кода — как &lt; &gt; &amp;.
- Примеры кода — на Python, JavaScript/Node.js, SQL, Bash, PowerShell; конфиги nginx, iptables,
  sshd_config и т. п. Показывай уязвимый и исправленный вариант рядом.
- Названия инструментов, стандартов и протоколов — в оригинале (Kerberos, ATT&CK, NIST SP 800-61).
  Термин при первом упоминании: русское название и английское в скобках.
- Ссылки на смежные уроки: «подробно — в уроке 7.2». Сетевые основы не пересказывай,
  ссылайся на курс «Сети для разработчиков».

БЕЗОПАСНОСТЬ И ЭТИКА
- Наступательные техники объясняй на уровне механизма и признаков. Допустимы классические
  учебные примеры (' OR 1=1 --, <script>alert(1)</script>, ../../etc/passwd, nmap -sV).
  Недопустимы: рабочие эксплойты под конкретные CVE, готовые вредоносные скрипты, обход
  конкретных EDR/антивирусов, инструкции по атаке на реальные сервисы.
- Где упоминаются сканирование, перебор или пентест — одна фраза о том, что это законно только
  на своих системах или с письменного разрешения, и ссылка на урок 0.5.
- Учётные данные и ключи в примерах — явно фиктивные (example.com, 203.0.113.0/24, AKIAEXAMPLE).

ТОЧНОСТЬ
- Пиши только то, в чём уверен. Версии, сроки и цифры указывай с годом («на 2025 год», «OWASP
  Top 10 2021»). Не придумывай статистику, CVE и цитаты.
- Устаревшие рекомендации помечай как устаревшие: MD5/SHA-1 для паролей, WEP/WPA, SSL 3.0 и
  TLS 1.0/1.1, обязательная смена пароля каждые 90 дней (NIST SP 800-63B от неё отказался).

ВОПРОСЫ
Самопроверка: 2 вопроса на урок, id 'q{M}-{N}a' и 'q{M}-{N}b' (N — номер урока).
Тест модуля: 12 вопросов, id 't{M}-1'…'t{M}-12'. Смесь типов на тест: 6–7 single,
1–2 multiple, 1 order, 1 match, 1–2 analyze, 0–1 input. Сложность: примерно 4 вопроса
difficulty 1, 6 — difficulty 2, 2 — difficulty 3.

Форматы (answer — индексы в исходном массиве options, интерфейс сам перемешивает варианты):
 { id, type:'single',   prompt, options:[4 варианта], answer:0, explanation, difficulty }
 { id, type:'multiple', prompt, options:[4–5], answer:[0,2], explanation, difficulty }
 { id, type:'order',    prompt, options:[4–6 шагов в ПРАВИЛЬНОМ порядке], answer:[0,1,2,3], explanation, difficulty }
 { id, type:'match',    prompt, pairs:[['слева','справа'], … 4 пары], explanation, difficulty }
 { id, type:'input',    prompt, answer:['22','tcp/22'], explanation, difficulty }  — короткий однозначный ответ
 { id, type:'analyze',  prompt, code:'фрагмент лога/вывода/кода', options:[4], answer:1, explanation, difficulty }

Требования к вопросам:
- Проверяют понимание и применение, а не память на определения. Хотя бы половина теста —
  сценарии: «в логе видно… что происходит?», «какой вариант кода безопасен?», «что сделать
  первым?».
- analyze — на реальных по виду данных: auth.log, Windows Event ID, вывод nmap, заголовки HTTP,
  фрагмент SQL-запроса, JSON-политика S3.
- Дистракторы правдоподобные, одной длины с правильным ответом. Без «все перечисленное»,
  без «ничего из перечисленного», без подсказок в формулировке.
- explanation — 1–2 предложения: почему верно и в чём ошибка самого частого неверного варианта.
- Каждый вопрос можно ответить по материалу уроков модуля.

СТИЛЬ
Русский язык, обращение на «вы» через повелительное наклонение («Проверьте…», «Храните…»),
без «мы рассмотрим» и «давайте». Короткие предложения. Без канцелярита, маркетинга и эмодзи. Типографика:
ёлочки «», длинное тире —, неразрывные пробелы не нужны.

САМОПРОВЕРКА ПЕРЕД ОТВЕТОМ
- Все темы из topics каждого урока раскрыты.
- В каждом уроке ровно 2 вопроса check, в тесте ровно 12, id уникальны и по шаблону.
- answer в order — [0,1,…] по длине options; в match пары в правильном соответствии.
- Объект валиден как JavaScript, в шаблонных строках нет неэкранированных ` и ${.
```

## Промт: course.js (виджеты, сценарий, шпаргалки)

Напиши файл web/courses/cyber-security/course.js для сайта с курсами. Ориентир по стилю и API —
web/courses/ai-agents/course.js и web/courses/network/course.js (приложены). Это ES-модуль:
утилиты импортируются из ../../assets/js/storage.js ($, esc, shuffle, toast, Store),
../../assets/js/game.js (Game) и ../../assets/js/engine.js (findLesson), RES — из ./content.js.

Файл должен экспортировать (export):
1. const COURSE = { id:'cyber-security', title:'Информационная безопасность для разработчиков',
   tagline:'…', journeyLabel:'Разбор инцидента', brand:'<svg 26×26 щит, акцент var(--accent)>' }

   ir, attck, cvss } — описания в structure.md, раздел «Интерактивные виджеты».
   Требования: чистый JS без библиотек; el.className = 'widget'; уникальные id через

Стили виджетов, которых нет в web/assets/css/base.css, — в web/courses/cyber-security/course.css.

## Сборка курса

Файлы курса лежат в `web/courses/cyber-security/`:

| Файл | Что внутри |
|---|---|
| `content.js` | импортирует модули в `MODULES`, задаёт `PLAN` — всю программу; ненаписанные модули показываются как «скоро» |
| `modules/mNN.js` | `export default {…}` — по файлу на модуль, результат промта выше |
| `glossary.js` | `export const GLOSSARY = [...]`, дополняется с каждым модулем |
| `resources.js` | `export const RES` — ссылки «Читать дальше», собраны скриптом из тем roadmap.sh |
| `course.js`, `course.css`, `theme.css` | настройки курса, виджеты, сценарий, шпаргалки, стили |
| `main.js` | точка входа страницы: передаёт контент и `course.js` в движок |

Порядок добавления модуля:

1. Сгенерировать модуль по промту и сохранить как `modules/mNN.js`.
2. Импортировать его в `content.js` и добавить в массив `MODULES` по порядку номеров.
3. Добавить термины модуля в `glossary.js` и виджеты модуля в `course.js` (и в `viewTools`).
4. Обновить `lessons` и `modules` курса в `web/assets/js/courses.js`.
5. Запустить `npm run check` в папке `web/` — валидатор должен вывести `OK`, линтер и сборка пройти без ошибок.
6. Пройти уроки, тест модуля и виджеты в браузере.
